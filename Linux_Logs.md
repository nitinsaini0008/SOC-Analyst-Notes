# Linux Logs

## About

Linux logs record system activities, user actions, application events, authentication attempts, and security-related information. These logs are essential for system administrators and SOC Analysts to troubleshoot issues, investigate incidents, and detect malicious activity.

Most Linux distributions store logs inside the **/var/log/** directory.

---

# What are Linux Logs?

Linux logs are text files generated by the operating system and applications.

They help administrators and security analysts monitor:

- User Logins
- Failed Logins
- SSH Activity
- System Startup
- System Errors
- Service Status
- Authentication
- Kernel Events

---

# Why Linux Logs are Important

Linux logs help to:

- Detect Intrusions
- Troubleshoot System Issues
- Investigate Security Incidents
- Monitor User Activity
- Meet Compliance Requirements
- Identify Malware

# Important Linux Log Files

## 1. auth.log

Ubuntu / Debian

```
/var/log/auth.log
```

Contains

- SSH Login
- Failed Login
- sudo Commands
- User Authentication

Useful for

- Brute Force Detection
- Privilege Escalation
- Unauthorized Access

---

## 2. secure

Red Hat / CentOS / Rocky Linux

```
/var/log/secure
```

Contains

- Authentication Events
- SSH Logins
- sudo Activity
- User Authentication

---

## 3. syslog

Ubuntu

```
/var/log/syslog
```

Contains

- System Events
- Service Messages
- Hardware Events
- General Logs

---

## 4. messages

Red Hat

```
/var/log/messages
```

Contains

- General System Messages
- Service Logs
- Network Events

---

## 5. dmesg

```
/var/log/dmesg
```

Contains

- Kernel Messages
- Hardware Detection
- Driver Loading

---

## 6. boot.log

```
/var/log/boot.log
```

Contains

- Boot Process
- Startup Services
- Initialization Events

---

## 7. cron

```
/var/log/cron
```

Contains

- Scheduled Jobs
- Cron Task Execution

Useful for detecting unauthorized scheduled tasks.

---

## 8. lastlog

Stores the last successful login for every user.

Command

```bash
lastlog
```

---

## 9. wtmp

Stores login and logout history.

Command

```bash
last
```

---

## 10. btmp

Stores failed login attempts.

Command

```bash
lastb
```

Useful for detecting brute-force attacks.

# Common Linux Log Commands

View Log

```bash
cat /var/log/auth.log
```

---

View Large Log

```bash
less /var/log/syslog
```

---

View Last Lines

```bash
tail /var/log/auth.log
```

---

Live Monitoring

```bash
tail -f /var/log/auth.log
```

---

Search Logs

```bash
grep "Failed" /var/log/auth.log
```

---

Search SSH Activity

```bash
grep "sshd" /var/log/auth.log
```

# Suspicious Indicators

- Multiple Failed SSH Logins
- Root Login Attempts
- Unknown User Creation
- Repeated sudo Failures
- Unexpected Cron Jobs

# Systemd Journal

Modern Linux distributions use **systemd**.

Useful Commands

View All Logs

```bash
journalctl
```

View Today's Logs

```bash
journalctl --since today
```

View SSH Logs

```bash
journalctl -u ssh
```

# Best Practices

- Monitor Authentication Logs
- Investigate Failed SSH Logins
- Disable Root SSH Login
- Enable Log Rotation
- Synchronize Time Using NTP
- Forward Logs to SIEM
- Secure Log Files
- Review Cron Jobs Regularly

# Real-Life Example

A SOC Analyst receives an alert about repeated SSH login failures.

Investigation shows:

- Hundreds of failed login attempts in **/var/log/auth.log**.
- The same IP address repeatedly targeting the **root** account.
- A successful login after several failures.

The analyst blocks the attacker's IP, disables direct root SSH access, resets the compromised account credentials, and reviews the server for persistence mechanisms.
